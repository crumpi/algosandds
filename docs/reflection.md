Through this module I wanted to get a better understanding of the implication of using various data structures and algorithms, how to assess them and when the choices do actually matter. By learning about how different data structures are represented in memory and what this actually means for different operations that one might want to perform on them, I leaned to better assess real world problems and how they map to the strengths and weaknesses of certain data structures. I learned about various search algorithms and how they perform in theory, as well as how advantages one over the other usually go alongside with disadvantages in other areas (e.g. cheap search in sorted arrays vs cost of keeping arrays sorted). I also learned various other things like sorting algorithms, complexity analysis and asymptotic notations, relevant mathematics, etc. Throughout this module I realized how nuanced problems usually are and how cautious I should be when analyzing the problem to figure out relevant solutions. As I've also attended the LU before hand, I did not learn any completely new things specifically, but refreshed my knowledge of the various topics we covered.  
I think I layed the ground for further exploration of actual implications in real world scenarios, specifically when comparing the choice between different algorithms and data structures in the context of other runtime costs of used programs, for example data base queries or third party tools. I assume these specifics will just show when running actual tests in real world setups where I can measure the actual impact of algorithm and data structure choices and set them in the context of these other factors.
